# Phase 18.5 Option 2 — Split Scope and Acceptance Contract

Status: selected and implementation-authorized
Decision date: 2026-08-01 local / 2026-08-02 UTC
Decision owner: Aaron

## Selected architecture

Option 2 splits durable Phase 18.5 World visual production from current imported-avatar acceptance.

Phase 18.5 continues to own the durable World visual-production outcomes: the repository grammar; semantic DOM, no-WebGL, reduced-motion, and context-loss truth; and the shared measurement methodology with its unchanged thresholds. Generated modular-avatar product acceptance and the July 26 native results are historical evidence for their exact inputs. The old kit and profile paths remain supported compatibility architecture, not dead code.

Current imported-avatar acceptance is a separately versioned, bounded track. It must use a current-input contract that distinguishes deterministic automatic functional/input verification from native visual or performance evidence. Current automatic CI policy for this slice is deterministic functional and input-contract proof only. Native evidence is explicit/manual and absent until separately approved; no July 26 record may be read as, rewritten into, rebound as, or declared to be current imported-avatar evidence.

Automatic CI also retains compatibility-only verification of the generated modular kit's static assets and the July 26 record's intrinsic integrity. That mode never compares historical fingerprints to current source bytes, never treats native/browser results as current or gating, and never rewrites inspection or evidence files. Current/native diagnostics remain a distinct explicit manual command and continue to fail closed on current-source drift.

## Preserved compatibility

The `aiw.avatar/0.18.5` base profile, the `0.11` migration reader, generated avatar-kit runtime, custom profiles, and mixed imported/custom World sessions remain reachable and supported for now. This decision does not authorize a sunset, archival, deletion, or weakening of those routes.

## Frozen exclusions

This authorization does not include legacy sunset or deletion; gesture inference; native evidence capture or recapture; hardware-result rebind; movement-authority repair; imported-avatar intake-timeout repair; legacy browser-compatibility repair; Phase 19 or Phase 20 work; dependency or package-manager changes; or commit, push, release, publication, deployment, tagging, or visibility changes.

## Evidence boundary

The historical Phase 18.5 reports, screenshots, measurements, and July 26 hardware record remain unchanged. A future native imported-avatar record requires separate approval and a new version. Until then, the current imported-avatar track may emit only deterministic machine-readable fingerprints of verified current inputs; it must not emit or imply native acceptance results.
