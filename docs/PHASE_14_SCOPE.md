## Objective

Complete the first one-agent development magic slice by connecting real structured tool events, bounded visual code explanations, one explicitly approved edit/test workflow, and a health-checked loopback project preview to exact World evidence without turning model prose or avatar motion into authority.

## Inherited boundaries

Phase 14 inherits every still-applicable project rule and accepted contract:

- AgentIntersect World remains independent; do not inspect or modify the original AgentIntersect checkout without explicit authorization.
- The supported topology is one trusted operator with local or trusted-LAN agents and views; there is no public room, cloud relay, multi-tenant identity, or arbitrary off-LAN ingress.
- Phase 12 text chat remains independent and usable when visualization, tools, or preview degrade.
- Phase 13 World Actions remain presentation-only. They do not execute tools, approve edits, launch processes, or mutate repositories.
- Structured runtime events and World-owned persisted records are authoritative; prose, inferred thought, animation, and browser-only state are not.
- Current versus previous/recovered/stale truth, cancellation, operator escape, reduced motion, keyboard/touch access, semantic fallback, and exact repository/session identity remain mandatory.
- Existing local/LAN safeguards against destructive mutation, secret leakage, accidental process escape, and unintended exposure remain intact.
- The deferred Phase 13 exact-root Discord → World continuation is not part of Phase 14 by default and must not be silently represented as fixed or green.

## Proposed decisions to freeze next session

These are proposals, not implementation authority.

### 1. One canonical vertical journey

Propose a single exact-repository journey:

1. attach one existing Hermes-backed agent session;
2. observe a real read/search tool event;
3. visualize the exact file, symbol, evidence, and bounded explanation;
4. request one edit through an explicit operator approval step;
5. show the resulting diff as current versus previous truth;
6. run one focused test through a bounded execution adapter;
7. launch or attach one loopback-only preview with a health check;
8. connect the final result back to the original tool, diff, test, and preview evidence.

Freeze the repository fixture, symbols, expected edit, focused test, preview command, health endpoint, and cancellation points before implementation.

### 2. Tool-event contract

Propose a strict versioned protocol for read/search/edit/test/preview lifecycle events with:

- adapter-owned session and repository identity;
- exact operation, correlation, parent, and sequence identifiers;
- bounded arguments and redacted display projections;
- requested, accepted, running, succeeded, failed, cancelled, and superseded states;
- explicit timestamps, provenance, and current/previous evidence links;
- no free-form shell command authority from model output;
- deterministic unknown-field rejection, idempotency, expiry, and replay limits.

### 3. Explanation contract

Propose bounded explanations tied to exact source evidence:

- line/symbol references must resolve against the current indexed revision;
- claims must distinguish source facts, runtime observations, test results, and model interpretation;
- stale or moved targets fail closed or surface authoritative continuity metadata;
- explanations remain useful in a semantic DOM view without WebGL;
- no chain-of-thought, hidden-reasoning simulation, or decorative thought bubbles.

### 4. Edit and approval boundary

Propose one narrow mutation path where:

- the operator sees the exact intended patch before approval;
- approval is explicit, scoped, single-use, and revocable before execution;
- repository root, allowed files, operation count, byte size, and timeout are bounded;
- pre-existing dirty work is preserved and never overwritten silently;
- failed or cancelled edits have truthful partial/rollback status;
- source mutation is performed by a dedicated adapter, never by World Actions or presentation code.

Freeze whether Phase 14 supports one-file replacement only or a bounded multi-file patch.

### 5. Test execution boundary

Propose an allowlisted focused-test adapter with:

- exact predeclared command templates rather than arbitrary shell strings;
- loopback/local execution only;
- bounded process count, runtime, output, and retained evidence;
- visible cancellation and truthful timeout/exit/signal state;
- no package publication, deployment, credential access, or background daemon escape.

Freeze the exact test command and fixture before implementation.

### 6. Preview boundary

Propose one loopback-only preview flow with:

- a predeclared start command and health endpoint;
- an OS-assigned or bounded configured port;
- readiness, unhealthy, stopped, failed, and cancelled states;
- explicit ownership and cleanup of the spawned process tree;
- no public ingress, tunnel, cloud deployment, or trusted-LAN binding unless separately selected;
- a browser view that remains optional and never becomes repository authority.

Freeze whether trusted-LAN preview is excluded entirely or retained as a later optional decision.

### 7. World presentation

Propose a bounded visual language for:

- exact tool/event status;
- file and symbol focus;
- current versus previous diff;
- test progress and result;
- preview readiness and health;
- operator approval, cancellation, and escape.

Movement may illustrate relationships but cannot imply tool success, repository mutation, test pass, or preview health before authoritative events say so.

### 8. Persistence and replay

Propose bounded durable summaries for operations, approvals, diffs, tests, and preview health while excluding secrets, raw transcripts, unbounded logs, and transient browser state. Freeze retention, row, byte, and replay ceilings.

### 9. Accessibility and degradation

Require keyboard-only, touch, reduced-motion, forced-colors, screen-reader, and no-WebGL equivalents. Every numbered operator step, status/result, current/previous label, approval/cancel control, and preview health state must remain reachable in semantic DOM order.

### 10. Performance evidence

Inherit Phase 13 raw-sample rules. Freeze additional ceilings for tool-event projection, diff rendering, test-log truncation, preview readiness, Long Tasks, and incremental heap on desktop plus constrained mobile/two-CPU fixtures. Preserve 10k/100k aggregate behavior without rendering whole-repository detail.

### 11. Acceptance evidence

Propose focused RED→GREEN tests plus one complete integrated gate covering:

- strict event/provenance/approval schemas;
- exact repository and session identity;
- safe edit/test/preview adapters;
- cancellation, timeout, restart, stale revision, duplicate, and cleanup behavior;
- truthful current/previous/status labels;
- desktop/mobile/keyboard/touch/reduced-motion/forced-colors/no-WebGL journeys;
- retained screenshot, short video, machine-readable performance data, and repository-mutation proof;
- complete `pnpm check`, Storybook build, production audit, fresh-copy verification, staged diff review, private push, and exact-SHA CI.

Keep the failed exact-root Discord → World continuation as a separately labeled backlog item. Next session must explicitly choose one of:

- authorize one bounded diagnostic/acceptance sub-slice with its own stop rule.

## Proposed acceptance

Phase 14 would be acceptable only when one approved local edit/test/preview journey is backed end-to-end by strict events and exact evidence; all controls and fallback views are usable; failures and cancellation remain truthful; source changes, processes, and preview listeners stay within the frozen boundary; cleanup is complete; and private exact-SHA CI is green.

## Non-goals

- autonomous or unapproved repository mutation;
- arbitrary shell/tool dispatch from model prose;
- broad IDE replacement, terminal emulator, or general workflow engine;
- multiple simultaneous projects, agents, or previews unless separately selected;
- public hosting, cloud deployment, public tunnels, account systems, or multi-tenancy;
- internet threat-model hardening beyond concrete local/LAN risks;
- package publication, release automation, tags, or public visibility;
- production code for the deferred Discord → World continuity feature without separate authorization;
- Blender, new avatar production, animation-set forks, or broad environment art;
- Phase 15+ work.
